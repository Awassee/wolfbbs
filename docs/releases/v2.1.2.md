# v2.1.2

WolfBBS v2.1.2 improves the consumer install experience. This release makes the standalone installer prefer packaged release bundles over source checkouts, turns release tarballs into real self-installable app bundles, and cleans up the installer language so it reads like a product installer rather than a developer workflow.

## What changed

- Improved the standalone install path.
  - `install.sh` now prefers the latest packaged GitHub Release bundle for the current platform.
  - if no matching release bundle is available, it falls back to a GitHub source archive.
  - `git` is now a last-resort path instead of the default mental model.
- Made release bundles actually install like a product.
  - added a bundled runtime `Dockerfile` based on the packaged binaries
  - release tarballs now contain the files needed to behave as a real install source
- Improved installer UX language.
  - the installer now talks about `app files` and `managed app dir`
  - dry-run output explains the bundle-first strategy clearly
- Updated verification and acceptance coverage.
  - installer regression tests now validate bundle-first dry-run behavior
  - acceptance/verifier wording now reflects packaged-bundle fallback instead of archive-only wording

## Why this release exists

The previous release line still worked, but it taught users the wrong model by centering source checkout behavior. v2.1.2 makes the default path feel more like installing a consumer app and less like managing a repository.
