# WolfBBS v1.1.8

This release is a security hardening pass focused on web auth, inbound mail, websocket login, and request trust boundaries.

## Highlights

- `cmd/wolfbbs-mailin` now requires shared-secret auth on `/ingest` and rejects the default dev token from public callers
- web `/mail/inbound` rejects the default dev token from public callers
- websocket login now rejects foreign browser origins instead of accepting any `Origin`
- password reset and ActivityPub base URLs no longer trust raw request host headers
- web login and password-reset request endpoints now enforce per-client throttles
- JSON webhook/chat endpoints are now size-bounded and strict-decoded
- outbound SMTP subject/recipient validation blocks header-injection attempts
- web and mail-in HTTP listeners now use explicit timeout settings

## Why it matters

The previous build had multiple trust-boundary weaknesses: public mail ingest could be abused, websocket login accepted hostile browser origins, reset links could be influenced by host headers, and JSON endpoints had no body bounds. This release closes those gaps without changing the product’s normal operator flow.
